# 11. 内核同步原语

> 多核 + 中断 + 软中断 = 大量并发场景。  
> 没有正确的同步，你的驱动就是定时炸弹。

---

## 为什么需要同步

Linux 内核有多个执行"流"可以同时访问同一份数据：

```
CPU 0          CPU 1
  │              │
  │              │
  ↓              ↓
读 data         读 data
  ↓              ↓
改 data         改 data
  ↓              ↓
写 data         写 data
  ↓              ↓
  └── 数据不一致 ──┘
```

还有更复杂的：中断、软中断、workqueue、用户进程——都可能同时访问同一份数据。

同步原语就是用来解决这种竞争的工具。

## 原子操作（最轻量）

```c
// 🔴 内核态
#include <linux/atomic.h>

atomic_t counter = ATOMIC_INIT(0);

atomic_inc(&counter);              // counter++
atomic_dec(&counter);              // counter--
atomic_add(5, &counter);           // counter += 5
atomic_sub(2, &counter);           // counter -= 2

int v = atomic_read(&counter);     // 读当前值
int v = atomic_inc_return(&counter); // counter++ 并返回新值

// 条件操作
bool success = atomic_dec_and_test(&counter);  // --counter == 0 ?

// bit 操作
void set_bit(0, &flags);           // flags |= (1 << 0)
void clear_bit(0, &flags);         // flags &= ~(1 << 0)
int test_and_set_bit(0, &flags);   // 测试并设置（原子）
int test_and_clear_bit(0, &flags); // 测试并清除（原子）
```

适用场景：
- 计数器（统计事件次数）
- 标志位（多位）
- 简单状态

⚠️ 原子操作只保护"单个变量"的原子读写。复杂结构还是要用锁。

## 自旋锁（Spinlock）

### 概念

```c
// 🔴 内核态
DEFINE_SPINLOCK(my_lock);   // 静态定义

spin_lock(&my_lock);
// 临界区
spin_unlock(&my_lock);
```

工作原理：
```
线程 A 获取锁 → 进入临界区
线程 B 想获取锁 → 死循环（自旋）等待
线程 A 释放锁 → 线程 B 立即获得锁
```

### 关键特性

| 特性 | 说明 |
|---|---|
| 忙等待 | 等锁时 CPU 一直空转（不调度）|
| 不能睡眠 | 持锁时绝对不能睡眠 |
| 适合短临界区 | 临界区代码应 < 100 行 |
| 多核友好 | 不同核可以同时持不同锁 |

### 完整用法

```c
// 🔴 内核态
unsigned long flags;

spin_lock_irqsave(&my_lock, flags);
// 临界区（这里既不能被中断打断，也不能被别的 CPU 抢锁）
spin_unlock_irqrestore(&my_lock, flags);
```

### 为什么用 irqsave 版本？

最安全的形式。`spin_lock_irqsave` 做三件事：
1. 关中断
2. 获取自旋锁
3. 保存之前的中断状态到 `flags`

`spin_unlock_irqrestore` 做相反的三件事：
1. 释放自旋锁
2. 开中断
3. 恢复之前的中断状态

**为什么要在持锁时关中断？**
防止死锁：如果你持锁时被中断打断，ISR 又想获取同一把锁，就会死锁。

### 什么时候用哪种 spin_lock？

| 函数 | 关中断 | 获取锁 | 适用场景 |
|---|---|---|---|
| `spin_lock` | ❌ | ✅ | 已知不在中断上下文 |
| `spin_lock_irq` | ✅ | ✅ | 已知在中断上下文 |
| `spin_lock_irqsave` | ✅ | ✅ | 不确定当前上下文（最安全）|
| `spin_lock_bh` | ❌（关软中断）| ✅ | 在软中断上下文，但不想关硬中断 |

### ⚠️ 持锁时的金科玉律

```
持锁期间禁止：
  ❌ msleep / ssleep
  ❌ schedule / yield
  ❌ kmalloc(GFP_KERNEL)
  ❌ copy_from_user
  ❌ mutex_lock（除特殊情况）
  ❌ 任何可能阻塞的调用
```

违反这些 = 死锁 + 系统 hang。

## 互斥锁（Mutex）

```c
// 🔴 内核态
DEFINE_MUTEX(my_mutex);

mutex_lock(&my_mutex);
// 临界区（这里可以睡眠！）
msleep(100);  // OK！
mutex_unlock(&my_mutex);
```

### 特性

| 特性 | 说明 |
|---|---|
| 睡眠等待 | 等锁时进程进入睡眠，让出 CPU |
| 可睡眠 | 持锁时可以睡眠 |
| 适合长临界区 | 临界区代码可以很长 |
| 只能用在进程上下文 | ISR 里不能用 |
| 同一锁不能递归 | 第二次 mutex_lock 会死锁 |

### spinlock vs mutex

| 场景 | 用哪个 |
|---|---|
| ISR 中 | spinlock |
| 持锁时间极短（< 几十行）| spinlock |
| 持锁时间可能长（可能睡眠）| mutex |
| 进程上下文 | mutex |
| 多核间短互斥 | spinlock |

⚠️ **不要混用**：持 mutex 时不能持 spinlock（除非是显式声明的 lockdep 顺序）。

## 读写锁（RWlock）

适合"读多写少"场景：

```c
// 🔴 内核态
DEFINE_RWLOCK(my_rwlock);

// 读
read_lock(&my_rwlock);
// 只读访问
read_unlock(&my_rwlock);

// 写
write_lock(&my_rwlock);
// 读写访问
write_unlock(&my_rwlock);
```

特性：
- 多个读者可以并发持有读锁
- 写者独占（排斥所有读者和其他写者）
- 适合配置参数、查找表等场景

新 API（推荐）：
```c
// RCU 是更现代的读多写少方案
rcu_read_lock();
rcu_dereference(ptr);
rcu_read_unlock();
```

## 顺序锁（Seqlock）

更激进的"读多写少"：

```c
// 🔴 内核态
DEFINE_SEQLOCK(my_seqlock);
unsigned int seq;

write_seqlock(&my_seqlock);
// 写
write_sequnlock(&my_seqlock);

do {
    seq = read_seqbegin(&my_seqlock);
    // 读（需要能容忍偶尔读到旧值）
    val = shared_data;
} while (read_seqretry(&my_seqlock, seq));
```

特性：
- 写优先：写者等待时阻止新的读者
- 读者几乎无开销（无锁）
- 读者可能读到旧数据（需要重试）

适用：jiffies、时间戳这种"宁可读旧不可阻塞"的场景。

## RCU（Read-Copy-Update）

最强大的读多写少方案，但最复杂：

```c
// 🔴 内核态

// 读者
rcu_read_lock();
p = rcu_dereference(global_ptr);
// 使用 p
rcu_read_unlock();

// 写者
new_p = kmalloc(...);
// 填充 new_p
rcu_assign_pointer(global_ptr, new_p);
synchronize_rcu();   // 等所有读者退出
kfree(old_p);        // 现在可以安全释放旧的
```

特性：
- 读者无锁、无原子操作、无内存屏障
- 写者开销大（要拷贝、等待、释放）
- 适合读极多写极少（路径查找、配置）

底软新人暂时不用深入理解，但要知道有这个工具。

## 完成量（Completion）

适合"等一件事做完"：

```c
// 🔴 内核态
DECLARE_COMPLETION(my_comp);

// 等
wait_for_completion(&my_comp);

// 唤醒
complete(&my_comp);
complete_all(&my_comp);  // 唤醒所有等待者
```

适用：固件加载完成、DMA 完成、设备初始化完成。

## wait_queue（等待队列）

让进程睡眠等待某个条件：

```c
// 🔴 内核态
DECLARE_WAIT_QUEUE_HEAD(my_wq);

// 等
wait_event_interruptible(my_wq, condition);

// 唤醒
wake_up(&my_wq);
wake_up_interruptible(&my_wq);
```

这是用户态 `read()` 阻塞读的实现基础：
```c
// 用户态
int n = read(fd, buf, sizeof(buf));
// 如果没数据，内核让进程睡眠在等待队列
// 当中断到达、workqueue 唤醒，read 才返回
```

## 实战：完整的同步示例

```c
// 🔴 内核态 — 一个有数据缓冲的驱动
struct mychip_priv {
    struct circ_buf buf;           // 环形缓冲区
    spinlock_t lock;               // 保护 buf
    wait_queue_head_t wq;          // 等数据的进程
    int data_ready;                // 数据是否准备好
};

static irqreturn_t mychip_isr(int irq, void *dev_id)
{
    struct mychip_priv *priv = dev_id;
    unsigned long flags;
    u32 data;

    // 读硬件
    data = ioread32(priv->regs + 0x200);
    iowrite32(0x1, priv->regs + 0x104);  // 清中断

    spin_lock_irqsave(&priv->lock, flags);
    // 写入环形缓冲区（持锁）
    circ_buf_write(&priv->buf, data);
    priv->data_ready = 1;
    spin_unlock_irqrestore(&priv->lock, flags);

    // 唤醒等待者（在持锁外！）
    wake_up_interruptible(&priv->wq);

    return IRQ_HANDLED;
}

// 用户态 read
static ssize_t mychip_read(struct file *filp, char __user *buf,
                           size_t count, loff_t *ppos)
{
    struct mychip_priv *priv = filp->private_data;
    unsigned long flags;
    int ret;

    // 等数据
    ret = wait_event_interruptible(priv->wq, priv->data_ready);
    if (ret)
        return -ERESTARTSYS;

    // 拷贝数据
    spin_lock_irqsave(&priv->lock, flags);
    count = min(count, circ_buf_len(&priv->buf));
    ret = copy_to_user(buf, priv->buf.head, count);
    circ_buf_consume(&priv->buf, count);
    if (circ_buf_len(&priv->buf) == 0)
        priv->data_ready = 0;
    spin_unlock_irqrestore(&priv->lock, flags);

    return ret ? -EFAULT : count;
}
```

## 死锁排查

### lockdep：内核死锁检测器

```bash
$ cat /proc/lockdep_stats
     lock dependency status:         enabled
     ... 

$ cat /proc/lockdep                   # 看当前的锁依赖图
```

如果发生死锁，内核会自动打印：

```
============================================
WARNING: possible circular locking dependency detected
5.15.0 #1 Tainted: G        W
--------------------------------------------
task1/123 is trying to acquire lock:
ffffffffaaaa0001 (&priv->lock){....}-{2:2}, at: mychip_isr+0x42/0x80

but task is already holding lock:
ffffffffbbbb0002 (&other->lock){....}-{2:2}, at: mychip_work+0x10/0x50
...
```

这种警告一定要认真看，说明有潜在死锁路径。

### 手动排查技巧

1. **画锁依赖图**：哪个函数持哪个锁，等哪个锁
2. **检查持锁顺序**：所有路径上锁 A 必须在锁 B 之前
3. **避免持锁调外部函数**：外部函数可能再调你

## 本章小结

✅ **本章速查表**

| 原语 | 用途 | 关键约束 |
|---|---|---|
| `atomic_*` | 单变量原子操作 | 不能保护复合操作 |
| `spin_lock` | 短临界区，忙等 | 不能睡眠 |
| `spin_lock_irqsave` | 不确定上下文的最安全 | 不能睡眠 |
| `mutex_lock` | 长临界区，睡眠等 | 只能在进程上下文 |
| `read_lock` / `write_lock` | 读多写少 | 简单场景 |
| `seqlock` | 极读多写少 | 读者可读旧值 |
| `rcu_*` | 极读多写少，最优 | 写者开销大 |
| `complete` / `wait_for_completion` | 等一次性事件 | 简单同步 |
| `wait_queue` | 阻塞睡眠 | 配 wake_up |

### 同步选择流程图

```
需要保护的数据？
  ├─ 单变量（int, flag）→ atomic_*
  └─ 多字段/复合结构 → 锁
       ├─ ISR 上下文 → spin_lock_irqsave
       ├─ 持锁时间极短（< 几十行）→ spin_lock
       ├─ 持锁时间长 → mutex
       └─ 读多写少 → RWlock / Seqlock / RCU
```
