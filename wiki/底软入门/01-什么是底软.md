# 01. 什么是底软

> 从这章开始，你会建立一个对"底层软件"的整体认知框架。  
> 应用层开发者和系统层开发者看代码的"同一行"，视角完全不同。

---

## 一句话定义

**底层软件（底软）** 是介于硬件与应用软件之间、负责把硬件能力"翻译"成软件可调用接口的代码层。

```
┌─────────────────────────────────┐
│     应用层 (PyTorch / TensorFlow) │
├─────────────────────────────────┤
│     中间件 (CUDA Runtime / ONNX Runtime) │  ← 这部分在某些团队也算"底软"
├─────────────────────────────────┤
│     系统层 (Linux 内核 / 驱动 / RTOS)  │  ← 典型的"底软"工作面
├─────────────────────────────────┤
│     固件层 (Firmware / Bootloader)    │  ← 严格意义上的"底软"
├─────────────────────────────────┤
│     硬件 (AI 芯片 / SoC)              │
└─────────────────────────────────┘
```

作为 AI 芯片公司的底软工程师，你主要工作在 **系统层 + 部分中间件层**。

## 底软工程师每天在干啥

| 工作类型 | 典型场景 | 占比（新人） |
|---|---|---|
| 驱动开发 | 给芯片上的某个 IP 写一个 Linux 驱动 | 30% |
| 驱动调试 | 别人写的驱动出问题，你来定位 | 25% |
| 用户态 SDK | 把驱动能力封装成 .so 给上层用 | 15% |
| 单元测试/验证 | 写测试用例、跑回归、自动化 | 15% |
| 文档编写 | 设计文档、API 文档、调试手册 | 10% |
| 跨团队沟通 | 和硬件、算法、上层软件对齐需求 | 5% |

**新人前 3 个月的特点**：80% 的时间在读别人的代码、修小 bug、写测试。只有 20% 在写新代码。**这很正常。**

## AI 芯片底软的特殊之处

相对传统嵌入式底软（网卡、存储、外设），AI 芯片底软有几个显著差异：

### 1. 你面对的是"加速器 IP"，不是传统外设

传统网卡：读写寄存器 → 数据包进出
AI 加速器：**上传指令队列 → 等待 DMA 完成 → 中断通知 → 读取结果**

这意味着你需要理解的：
- 计算图（graph）的概念
- Tensor 在内存里的布局（NHWC、NCHW、block tile）
- 指令预取/派发机制
- 大块数据搬运（DMA）

### 2. 性能是第一优先级

传统驱动的衡量标准是"能不能用"，AI 芯片驱动还要"够不够快"：
- 中断延迟不能高（影响算子调度）
- DMA 拷贝要尽量减少 CPU 参与（zero-copy）
- 多核下要避免锁竞争（用 per-CPU 队列、无锁 ring buffer）

### 3. 软硬件协同设计

芯片设计阶段，硬件和软件是**协同定义**的：
- 硬件给你留什么寄存器、什么中断
- 软件期望硬件有什么能力

作为底软，你可能参与**寄存器手册的 review**、**固件接口的设计讨论**。这在传统嵌入式里是少见的。

### 4. 工具链复杂

AI 芯片底软的工具链通常包括：
- 编译器（可能是 LLVM 的定制后端）
- 模拟器（功能仿真、性能仿真）
- Profiling 工具（trace、性能火焰图）
- 上层框架适配（PyTorch 插件、ONNX Runtime EP）

## 底软 vs 应用软件：思维差异

| 维度 | 应用软件 | 底软 |
|---|---|---|
| 资源管理 | malloc/free（出错就崩） | kmalloc/kfree（出错可能 panic 整个系统）|
| 错误处理 | 返回 errno，调用者处理 | 必须谨慎：可能没有调用者、没有进程上下文 |
| 并发 | 多线程 + 锁 | 中断上下文、软中断、workqueue、per-CPU |
| 调试 | printf + GDB | printk + GDB + kgdb + 示波器（看芯片引脚）|
| 测试 | 单元测试 + 集成测试 | 单元测试 + 硬件 in-the-loop + 压力测试 |
| 代码风格 | 自由 | 严格（Linux 内核有 CodingStyle）|
| 性能 | 通常够用就好 | 每微秒都要抠 |

**最核心的差异**：**底软代码出错的后果是"整台机器挂掉"，不是"我这个进程挂掉"。** 这个意识要永远绷着。

## 底软工程师的核心素质

不是所有技能都能临时学，下面这些是底软工程师的"基本素养"：

1. **会读芯片手册** — 动辄几百页的寄存器手册，要能快速定位关键章节
2. **抽象能力** — 把硬件行为抽象成软件模型（状态机、队列、缓冲）
3. **系统视角** — 一个 bug 可能在驱动、在内核、在硬件，问题域是立体的
4. **耐心** — 调试一个内核 panic 可能花一整天
5. **英语阅读** — 大部分一手资料都是英文（LKML、内核文档、芯片手册）

## 本章小结

✅ **本章速查表**

- **底软** = 硬件与软件之间的翻译层，包括固件、内核驱动、系统层中间件
- **AI 芯片底软** 的核心特征：加速器抽象、性能敏感、软硬件协同
- **底软思维** 的核心：出错后果严重，必须极度谨慎
- **新人阶段** 主要是读代码 + 改 bug + 写测试，写新代码的比例不大
