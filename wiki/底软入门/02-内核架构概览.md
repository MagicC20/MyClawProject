# 02. 内核架构概览

> 在写第一个驱动之前，你需要对 Linux 内核有一个"地形图"级别的认知。  
> 应用软件工程师很容易把内核当成一个"黑盒 API 提供者"，但底软工程师必须理解它的内部结构。

---

## 内核 vs 用户态

Linux 系统分两层：**用户态（User Space）** 和 **内核态（Kernel Space）**。

```
用户态：你的应用、Shell、GUI
───────────────────────────  ← 系统调用接口（syscall）
内核态：内核本身、驱动、文件系统、网络栈
───────────────────────────  ← 硬件边界
硬件
```

### 为什么分两层？

```
应用：  malloc(100MB)    → 内核：检查物理内存够不够 → 给它分配
应用：  read(fd, buf, n) → 内核：找到文件 → 把数据从磁盘读到内核缓冲区 → 拷到 buf
应用：  sleep(1)         → 内核：把进程从运行队列挪走 → 1秒后唤醒
```

应用软件的所有"魔法"——文件操作、网络、内存分配、多任务——**都是内核在背后实现的**。

应用软件和内核的边界是**系统调用（syscall）**：
- 应用通过 `syscall` 进入内核
- 内核完成操作后返回结果
- 这是唯一的合法跨界方式

### 内核态有什么特权？

- 直接访问所有物理内存
- 可以执行特权 CPU 指令
- 可以访问硬件寄存器（MMIO）
- **可以挂掉整台机器**

## 内核全景图

Linux 内核大约 3000 万行代码（5.x），但可以分成几个核心子系统：

```
                    ┌──────────────────┐
                    │   系统调用接口    │  ← 应用和内核的边界
                    └────────┬─────────┘
        ┌────────────────────┼────────────────────┐
        │                    │                    │
   ┌────▼─────┐      ┌──────▼──────┐      ┌──────▼──────┐
   │ 进程管理  │      │   内存管理   │      │   文件系统   │
   │ (Process) │      │   (MM)      │      │   (VFS)     │
   └────┬─────┘      └──────┬──────┘      └──────┬──────┘
        │                   │                    │
        │            ┌──────▼──────┐             │
        │            │   设备驱动   │ ←───────────┘
        │            │   (Drivers) │   块设备、网络、字符设备
        │            └──────┬──────┘
        │                   │
   ┌────▼─────┐      ┌──────▼──────┐
   │   调度    │      │   网络栈     │
   │ (Sched)  │      │   (Net)     │
   └──────────┘      └─────────────┘
```

### 各子系统一句话职责

| 子系统 | 干什么 | 底软会涉及的深度 |
|---|---|---|
| 进程管理 | 创建/销毁/调度进程 | 中级（理解 task_struct、调度上下文）|
| 内存管理 | 物理/虚拟内存、页表 | 高级（驱动里 mm/io 都要懂）|
| 文件系统 | VFS 抽象、ext4、proc | 初级（驱动通常不直接碰 FS）|
| 设备驱动 | 字符/块/网络设备 | **核心** |
| 网络栈 | TCP/IP、socket | 偶尔（网卡驱动会涉及）|
| 调度 | CFS、实时调度 | 中级（实时任务会用）|

## 内核源码目录结构

拿到一份内核源码（`/usr/src/linux-headers-$(uname -r)` 或者从 [kernel.org](https://www.kernel.org/) 下载完整版）：

```
linux/
├── arch/           ← 架构相关代码（arm、arm64、x86...）
├── drivers/        ← 所有设备驱动 ← 你以后会经常来这里
│   ├── char/       ← 字符设备驱动
│   ├── net/        ← 网络设备
│   ├── gpu/        ← GPU 驱动（AI 芯片可能在这里或独立）
│   ├── dma/        ← DMA 引擎
│   └── ...
├── fs/             ← 文件系统
├── kernel/         ← 进程调度、信号、电源管理等核心
├── mm/             ← 内存管理
├── net/            ← 网络协议栈
├── include/        ← 头文件
│   ├── linux/      ← 跨架构头文件
│   └── asm-*/      ← 架构相关头文件
├── Documentation/  ← 内核自带文档（重要！）
├── Makefile        ← 顶层 Makefile
└── Kconfig         ← 内核配置
```

**新手必去的几个地方：**
- `drivers/char/` — 看简单的字符设备驱动样例
- `drivers/base/` — platform、device 等基础设施
- `Documentation/driver-api/` — 驱动开发 API 文档
- `include/linux/` — 看常用 API 的声明和注释

## 内核版本选择

新人推荐使用 **Linux 5.10 / 5.15 / 6.1** 这类 LTS 版本：

```
查看当前内核版本：
  $ uname -r
  5.15.0-89-generic

推荐版本（2024-2025 时点）：
  - Ubuntu 22.04 LTS  → 5.15
  - Ubuntu 24.04 LTS  → 6.8
  - CentOS Stream 9   → 5.14
  - Debian 12         → 6.1
```

⚠️ **不要**用 mainline（6.9+ 等最新版）做学习环境 —— 改动太快，文档/教程跟不上。

## 内核的"模块化"设计

Linux 内核支持两种构建方式：
1. **编译进内核（built-in）**：驱动代码直接编译到内核镜像里
2. **编译成模块（module）**：独立 .ko 文件，可以动态加载/卸载

驱动开发几乎都用模块方式：
```
优点：
  - 不需要重新编译整个内核
  - 可以动态加载/卸载，方便调试
  - 不同设备用不同模块，灵活

缺点：
  - 略微增加内存占用（可忽略）
  - 模块签名验证（生产环境会开启）
```

## 一个完整的内核启动流程（简化版）

```
BIOS/UEFI
    ↓
Bootloader (GRUB)
    ↓
解压缩内核 → 跳到 entry point
    ↓
start_kernel()  ← 内核 C 入口
    ↓
setup_arch()       ← 架构初始化
sched_init()       ← 调度器初始化
mm_init()          ← 内存管理初始化
driver_init()      ← 驱动基础设施
    ↓
do_basic_setup()   ← 各种子系统初始化
    ↓
prepare_namespace() ← 挂载根文件系统
    ↓
init/main.c: kernel_init_freeable()
    ↓
run_init_process() ← 启动 /sbin/init → 用户态
```

**关键点**：内核启动是一个**有序的初始化序列**，每个子系统按依赖顺序初始化。驱动通过 `module_init` 注册的初始化函数会在对应阶段被调用。

## 本章小结

✅ **本章速查表**

- 内核态 vs 用户态：边界是 syscall，特权完全不同
