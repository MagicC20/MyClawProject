# 09. 设备树入门

> 设备树是 Linux 嵌入式的事实标准。  
> 不会读设备树，就读不懂芯片手册 + 内核驱动的桥梁。

---

## 设备树是什么

**设备树（Device Tree）**：一种用文本格式描述硬件的数据结构，内核启动时解析它，把硬件信息传给驱动。

为什么要用它？
- 老办法：每个板子写一个 C 文件（arch/arm/mach-xxx/board-xxx.c）
  - 问题：几百个板子 = 几百个 C 文件，内核臃肿
- 新办法：板子信息放到设备树文件（.dts），内核只有一个
  - 内核可执行文件通用，板子信息外挂

```
设备树源文件（.dts）      设备树编译      设备树二进制（.dtb）
   文本                    dtc              二进制
                                         内核启动时解析
                                              ↓
                                          设备树展开（/proc/device-tree）
```

## 设备树源文件基础

### 文件类型

| 后缀 | 含义 |
|---|---|
| `.dts` | 设备树源文件（一个 SoC 或一个板子）|
| `.dtsi` | 设备树头文件（被 include，描述 SoC 共性）|
| `.dtb` | 设备树编译产物 |
| `.dts.dts` | 编译 .dtb 时用的临时文件 |

### 文件结构骨架

```dts
/dts-v1/;        ← 版本声明（必须）
/plugin/;        ← 可选：表示这个 .dts 可以被其他 .dts include

#include "skeleton.dtsi"   ← SoC 通用定义（来自 SDK）

/ {
    #address-cells = <2>;   ← 子节点 reg 属性的地址用几个 cell 表示
    #size-cells = <2>;      ← 子节点 reg 属性的大小用几个 cell 表示
    model = "My Chip Board";
    compatible = "vendor,board";

    cpus { ... };           ← CPU 定义
    soc { ... };            ← SoC 内部外设
    chosen { ... };         ← 内核启动参数（cmdline, initrd 等）
    aliases { ... };        ← 别名（如 serial0 = &uart0）
};
```

## 节点和属性

### 节点的语法

```dts
label: node-name@unit-address {
    property-name = "value";   ← 属性
    property-array = <0x10 0x20>;
    child-node { ... };        ← 子节点
};
```

**节点命名规则**：
- `node-name`：字母、数字、逗号、点、横线、下划线
- `@unit-address`：可选，但通常建议加（如寄存器地址、I2C 地址）

### 属性类型

#### 1. 字符串

```dts
compatible = "vendor,device";
status = "okay";
```

#### 2. 32 位整数数组

```dts
reg = <0xe0000000 0x1000>;     // 起始地址 + 大小
interrupts = <0 32 4>;          // 类型 + 中断号 + 触发方式
clocks = <&clock 5>;            // 引用 + cell 数
```

#### 3. 字节序列（用方括号）

```dts
mac-address = [00 11 22 33 44 55];
```

#### 4. 字符串列表

```dts
compatible = "vendor,mychip", "vendor,generic-chip";
```

#### 5. 布尔值（存在即真）

```dts
dma-coherent;       ← 没有值，表示"yes"
```

## 关键属性详解

### `compatible` — 最常用

```dts
compatible = "vendor,specific-device", "vendor,generic-class";
```

驱动通过这个字符串匹配。匹配逻辑：
1. 驱动 `of_match_table` 里列出支持的 compatible
2. 内核找到匹配的 device node → 调用 probe

推荐格式：`<vendor>,<chip>`。

### `reg` — 寄存器描述

```dts
mychip@0xe0000000 {
    reg = <0x0 0xe0000000 0x0 0x1000>;   // addr-high addr-low size-high size-low
    //       ↑            ↑
    //       高 32 位       低 32 位
};
```

`#address-cells` 和 `#size-cells` 决定 `reg` 用多少个 cell。

注意：
- 64 位 SoC（arm64）通常用 2 个 cell 表示地址（高 32 + 低 32）
- 32 位 SoC（arm32）通常用 1 个 cell

### `interrupts` — 中断描述

```dts
mychip@0xe0000000 {
    interrupts = <0 32 4>;   // 含义见下
};
```

第一个 cell（中断类型）：
- 0 = SPI（Shared Peripheral Interrupt，普通外设中断）
- 1 = PPI（Private Peripheral Interrupt，CPU 私有中断）

第二个 cell（中断号）：
- SPI：0~991 的全局号

第三个 cell（触发方式，flags）：
- 1 = 低电平触发
- 2 = 上升沿
- 4 = 高电平
- 8 = 下降沿

### `status` — 启用/禁用

```dts
mychip@0xe0000000 {
    compatible = "vendor,mychip";
    reg = <...>;
    status = "okay";    // 启用
    // status = "disabled";  // 禁用（驱动不会 probe）
};
```

### `clocks` 和 `clock-names`

```dts
mychip@0xe0000000 {
    clocks = <&clock 5>, <&clock 6>;
    clock-names = "bus", "core";
};
```

## 一个完整示例

```dts
/ {
    #address-cells = <2>;
    #size-cells = <2>;
    
    soc {
        #address-cells = <2>;
        #size-cells = <2>;
        compatible = "simple-bus";
        
        uart0: serial@0xe0001000 {
            compatible = "vendor,uart";
            reg = <0x0 0xe0001000 0x0 0x1000>;
            interrupts = <0 24 4>;
            clocks = <&clock 1>;
            status = "okay";
        };
        
        mychip@0xe0000000 {
            compatible = "vendor,mychip";
            reg = <0x0 0xe0000000 0x0 0x1000>;
            interrupts = <0 32 4>;
            clocks = <&clock 5>, <&clock 6>;
            clock-names = "reg", "core";
            resets = <&reset 3>;
            dmas = <&dma0 0>, <&dma1 1>;
            dma-names = "tx", "rx";
            status = "okay";
        };
        
        dma0: dma@0xe0010000 {
            compatible = "vendor,dma";
            reg = <0x0 0xe0010000 0x0 0x200>;
            interrupts = <0 40 4>;
            #dma-cells = <1>;
        };
    };
    
    chosen {
        stdout-path = "serial0:115200n8";
        bootargs = "console=ttyS0 root=/dev/mmcblk0p2";
    };
};
```

## 内核中读取设备树

### 基础 API（`<linux/of.h>`）

```c
// 🔴 内核态

// 1. 读字符串属性
const char *str = of_get_property(np, "status", NULL);
// 等价于：np->properties["status"] 字符串值

// 2. 读 u32 属性
u32 val;
of_property_read_u32(np, "reg", &val);

// 3. 读 u32 数组
u32 arr[4];
int n = of_property_read_u32_array(np, "reg", arr, 4);

// 4. 读字符串
char buf[64];
of_property_read_string(np, "status", buf);

// 5. 找子节点
struct device_node *child;
for_each_child_of_node(np, child) {
    // 处理每个子节点
}

// 6. 找 compatible 匹配的节点
struct device_node *np = of_find_compatible_node(NULL, NULL, "vendor,mychip");
```

### 在 platform 驱动中读属性

```c
// 🔴 内核态
static int mychip_probe(struct platform_device *pdev)
{
    struct device_node *np = pdev->dev.of_node;
    u32 val;
    const char *str;
    int ret;

    // 读 u32
    ret = of_property_read_u32(np, "my-prop", &val);
    if (ret) {
        dev_err(&pdev->dev, "missing my-prop\n");
        return ret;
    }

    // 读字符串
    ret = of_property_read_string(np, "my-string", &str);
    if (ret) {
        // 用默认值
        str = "default";
    }

    return 0;
}
```

### 读子节点

```c
// 🔴 内核态
struct device_node *child;

for_each_child_of_node(np, child) {
    u32 reg;
    of_property_read_u32(child, "reg", &reg);
    pr_info("child reg=0x%x\n", reg);
}
```

## 编译设备树

```bash
# 把 .dts 编译成 .dtb
$ dtc -I dts -O dtb -o mychip.dtb mychip.dts

# 反编译 .dtb 查看
$ dtc -I dtb -O dts mychip.dtb > recovered.dts

# 内核构建系统自动编译
$ make mychip_defconfig
$ make dtbs
# 生成的 .dtb 在 arch/arm64/boot/dts/vendor/
```

## 运行时查看设备树

```bash
# 系统启动后查看展开的设备树
$ ls /sys/firmware/devicetree/base/
$ cat /sys/firmware/devicetree/base/soc/mychip@e0000000/compatible
vendor,mychip

# 看设备树里某个节点的属性
$ hexdump -C /sys/firmware/devicetree/base/soc/mychip@e0000000/reg
```

## overlay：动态修改设备树

设备树 overlay（DTO）允许**运行时**给设备树加节点（不需要重新编译 .dtb）。

```dts
// 📄 mychip-overlay.dts
/dts-v1/;
/plugin/;

&{/} {
    my_extra_chip {
        compatible = "vendor,extra-chip";
        reg = <0x0 0xe0020000 0x0 0x100>;
        status = "okay";
    };
};
```

应用：
```bash
# 启动时加载
$ sudo dtoverlay -d . mychip-overlay.dtbo

# 运行时加载
$ sudo dtoverlay mychip-overlay.dtbo
```

## 设备树调试技巧

```bash
# 1. 编译时打印
$ dtc -I dts -O dtb mychip.dts -W no-graph_child_address

# 2. 内核启动参数加 debug
$ dmesg | grep -i "of:"

# 3. 看 /proc/device-tree
$ ls -R /proc/device-tree/soc/

# 4. 用 of_dump 工具
$ ls /sys/kernel/debug/devicetree/
```

## 本章小结

✅ **本章速查表**

| 元素 | 用途 |
|---|---|
| `.dts` | 设备树源文件 |
