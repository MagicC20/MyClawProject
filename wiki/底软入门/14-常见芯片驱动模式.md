# 14. 常见芯片驱动模式

> 最后一章。看完这些，你至少能读懂 80% 的芯片驱动代码。  
> 这些都是"套路"，不是死规则，实际情况可能有变体。

---

## 模式 1：简单字符设备 + ioctl

**适用**：芯片的状态查询、控制命令、调试接口

我们已经详细讲过。这是最简单的模式。

```
用户态：open("/dev/mychip") → ioctl(fd, CMD, arg) → close(fd)
驱动：file_operations + unlocked_ioctl 实现
```

典型代码量：300~500 行

---

## 模式 2：UIO（Userspace I/O）

**适用**：驱动逻辑简单，但延迟敏感，需要用户态完全控制

```c
// 🔴 内核态 — UIO 驱动极简
static irqreturn_t mychip_uio_handler(int irq, struct uio_info *dev_info)
{
    return IRQ_HANDLED;  // 只是告诉用户中断来了
}

static int mychip_uio_probe(struct platform_device *pdev)
{
    struct uio_info *info = devm_kzalloc(&pdev->dev, sizeof(*info), GFP_KERNEL);

    info->name = "mychip-uio";
    info->version = "1.0";
    info->irq = platform_get_irq(pdev, 0);
    info->irq_flags = IRQF_TRIGGER_HIGH;
    info->handler = mychip_uio_handler;

    info->mem[0].addr = (phys_addr_t)ioremap(...);  // 寄存器基址
    info->mem[0].size = 0x10000;
    info->mem[0].memtype = UIO_MEM_PHYS;

    return uio_register_device(&pdev->dev, info);
}
```

```c
// 🟢 用户态 — UIO 用户态程序
int fd = open("/dev/uio0", O_RDWR);
uint32_t *regs = mmap(NULL, 0x10000, PROT_READ | PROT_WRITE,
                      MAP_SHARED, fd, 0);

// 直接读写寄存器
regs[0x300 / 4] = 0x1;  // 启动 DMA

// 等中断
uint32_t count;
read(fd, &count, sizeof(count));  // 阻塞等中断
```

UIO 的优势：
- 内核驱动极简（只是"传递"中断和寄存器访问）
- 用户态可以完全控制硬件（实现复杂的协议）
- 调试方便（用户态崩溃不影响内核）

UIO 的劣势：
- 用户态要自己写寄存器级别的代码
- 没有标准的设备模型抽象

**典型使用场景**：FPGA、定制加速器原型、低延迟数据采集。

## 模式 3：VFIO

**适用**：需要 DMA 隔离、性能极致、安全要求高

```c
// 🔴 内核态 — VFIO 驱动核心
static int mychip_vfio_probe(struct platform_device *pdev)
{
    struct vfio_device *vdev;
    // ... 初始化 ...

    vfio_register_device(&vdev);
    return 0;
}
```

VFIO 比 UIO 更强大：
- IOMMU 保护（设备只能访问授权的内存）
- 完全的用户态驱动支持
- 适合虚拟化场景

**典型使用场景**：GPU 直通（DPDK/SPDK/SPDK-like 场景）、用户态网络栈。

底软新人不太会直接写 VFIO 驱动，但要知道它的存在。

## 模式 4：misc 设备（杂项设备）

**适用**：单一设备实例，不需要主次设备号管理

```c
// 🔴 内核态
#include <linux/miscdevice.h>

static const struct file_operations mychip_misc_fops = {
    .owner = THIS_MODULE,
    .open  = mychip_open,
    .read  = mychip_read,
    .write = mychip_write,
    .unlocked_ioctl = mychip_unlocked_ioctl,
};

static struct miscdevice mychip_misc = {
    .minor = MISC_DYNAMIC_MINOR,   // 内核自动选 minor
    .name  = "mychip",              // 自动创建 /dev/mychip
    .fops  = &mychip_misc_fops,
    .mode  = 0666,
};

static int mychip_probe(struct platform_device *pdev)
{
    return misc_register(&mychip_misc);
}

static int mychip_remove(struct platform_device *pdev)
{
    misc_deregister(&mychip_misc);
    return 0;
}
```

优势：
- 自动创建 /dev/xxx
- 不需要 alloc_chrdev_region / cdev_init / cdev_add 一堆操作
- 设备类注册也省了

**Linux 内核里大量驱动用 misc**（看 `drivers/char/` 一半都是 miscdevice）。

## 模式 5：字符设备 + MMAP（高性能数据交换）

**适用**：需要大块数据零拷贝传输

```c
// 🔴 内核态 — 已经有 dma_alloc_coherent 的 buffer

static int mychip_mmap(struct file *filp, struct vm_area_struct *vma)
{
    struct mychip_priv *priv = filp->private_data;
    size_t size = vma->vm_end - vma->vm_start;

    if (size > priv->buf_size)
        return -EINVAL;

    // 把一致性 DMA buffer 映射到用户空间
    return dma_mmap_coherent(&pdev->dev, vma,
                             priv->buf_cpu,
                             priv->buf_dma,
                             size);
}
```

**注意**：`dma_mmap_coherent` 是专门的 helper，会正确处理 cache 一致性。

## 模式 6：计算任务队列（Compute Queue）

**适用**：AI 推理加速、异步任务处理

```c
// 🔴 内核态 — 任务描述符
struct mychip_task {
    u64 input_addr;       // 输入数据 DMA 地址
    u64 output_addr;      // 输出数据 DMA 地址
    u32 input_size;
    u32 output_size;
    u32 model_id;         // 用哪个模型
    u32 flags;            // 中断使能等
};

// 用户态提交任务
static long mychip_submit_task(struct file *filp, unsigned long arg)
{
    struct mychip_priv *priv = filp->private_data;
    struct mychip_task task;

    if (copy_from_user(&task, (void __user *)arg, sizeof(task)))
        return -EFAULT;

    // 写入任务队列（环形缓冲区）
    spin_lock(&priv->queue_lock);
    int slot = priv->queue_tail;
    priv->queue[slot] = task;
    priv->queue_tail = (slot + 1) % QUEUE_SIZE;
    spin_unlock(&priv->queue_lock);

    // 写硬件寄存器触发
    iowrite32(slot, priv->regs + 0x500);

    return 0;
}

// ISR 处理完成的任务
static irqreturn_t mychip_isr(int irq, void *dev_id)
{
    struct mychip_priv *priv = dev_id;
    u32 status = ioread32(priv->regs + 0x100);

    if (status & TASK_COMPLETE) {
        u32 done_id = ioread32(priv->regs + 0x504);
        priv->queue_head = done_id + 1;
        wake_up(&priv->task_wq);
    }

    iowrite32(status, priv->regs + 0x104);  // 清中断
    return IRQ_HANDLED;
}
```

## 模式 7：子系统框架（DMA Engine, Regulator, Clock...）

**适用**：复用内核已有的子系统抽象

如果你写的驱动涉及：
- DMA：用 `drivers/dma/` 的 dmaengine 框架
- 时钟：用 clk API
- 电源管理：用 PM Runtime
- GPIO：用 gpiolib
- pinctrl：用 pinctrl 子系统

这些子系统都是**框架**，驱动注册到框架里，由框架统一管理。

```c
// 例：用 dmaengine API
struct dma_chan *chan = dma_request_chan(&pdev->dev, "tx");

struct dma_async_tx_descriptor *desc = dmaengine_prep_dma_memcpy(
    chan, dst, src, len, DMA_MEM_TO_MEM);
desc->callback = my_callback;
dmaengine_submit(desc);
dma_async_issue_pending(chan);
```

## 模式 8：MFD（Multi-Function Device）

**适用**：一个芯片有多个子功能（如 PMIC、SoC）

```c
// 🔴 内核态 — MFD 父驱动
static struct mfd_cell mychip_cells[] = {
    { .name = "mychip-gpu", .resources = ..., },
    { .name = "mychip-dsp", .resources = ..., },
    { .name = "mychip-vpu", .resources = ..., },
};

static int mychip_probe(struct platform_device *pdev)
{
    return mfd_add_devices(&pdev->dev, PLATFORM_DEVID_AUTO,
                           mychip_cells, ARRAY_SIZE(mychip_cells),
                           NULL, 0, NULL);
}
```

每个子设备作为独立 platform_device 注册给子驱动。

## 模式 9：用户态驱动框架（SPDK/DPDK/RDMA）

**适用**：超高性能场景（数据中心、网络）

完全绕过内核，直接从用户态访问硬件（通过 UIO/VFIO/io_uring）。

底软新人不会直接用，但要知道它们的存在和适用场景。

## 选型流程

拿到一个新芯片驱动任务，怎么选模式？

```
Q1: 驱动逻辑复杂吗？
  ├─ 简单（纯寄存器读写 + 中断）→ UIO
  └─ 复杂（需要资源管理、电源管理等）→ 内核驱动

Q2: 性能要求？
  ├─ 极致延迟 → UIO / VFIO + 用户态驱动
  ├─ 高吞吐 → 内核驱动 + DMA + 多队列
  └─ 一般 → 内核驱动 + ioctl

Q3: 安全要求？
  ├─ 高（多租户、虚拟化）→ VFIO + IOMMU
  └─ 一般 → 内核驱动即可

Q4: 设备类型？
  ├─ 单一实例 → misc device
  ├─ 多实例 → char device with minor
  ├─ 网络加速 → net device（甚至 netdev-egress 风格）
  └─ 复杂多功能 → MFD

Q5: 数据交换模式？
  ├─ 命令/控制 → ioctl
  ├─ 流式数据 → read/write
  ├─ 大块零拷贝 → mmap
  └─ 异步任务 → 任务队列
```

## 真实芯片驱动的样子

去 GitHub 搜几个真实驱动看看（建议在入职前看）：

## 一些软技能

### 1. 学会问问题

问之前先自己搜。看代码、看 commit log、看 issue tracker。
找不到再问，问题要具体：
- ❌ "这个驱动有问题"
- ✅ "我的场景是 X，发现 Y 现象，看了 Z 代码，怀疑是 A 原因。"

### 2. 学会读代码

驱动代码量大（几千行），不要逐行读。读代码的技巧：

1. **从 probe 开始读**：理解初始化流程
2. **看 ioctl 表**：理解所有命令的功能
3. **画流程图**：把状态机画出来
4. **看 git log**：理解代码为什么这样写
5. **看注释和 TODO**：前人留下的线索

### 3. 学会复盘

- 每天工作完记笔记
- 每周 review 一次，写下学到的
- 每个 bug 都做 root cause analysis
- 整理"踩坑手册"（推荐用 GitHub repo 维护）

### 4. 主动暴露风险

底软新人的常见错误：藏着 bug 不说，期望它自己消失。
正确做法：发现 bug 立刻告诉主管 + 同事，集体讨论。
